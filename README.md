# Deutsch in 30 Tagen

A self-study German A1 course as a single interactive web page: 30 chapters, one per day, each planned to fit 30 minutes, with recorded German audio for every dialogue line and every word.

- **Public site:** https://azizjonkasimov.github.io/german-a1-book/ (GitHub Pages, built from `index.html` on `main`)
- **Claude page:** https://claude.ai/artifact/JApiNe9jVhy4qqwuYo5XSz (private link, needs a Claude sign-in)
- **Run locally:** `node serve.js`, then open http://localhost:8765

## What is in a chapter

Each day has a warm-up (3 min), a dialogue with playback (5 min), about 20 words of vocabulary with a self-test mode (7 min), one or two grammar points (7 min), exercises with hidden answers (6 min) and a speaking or writing task (2 min), followed by a tip about life in Germany and an "I can now" checklist. Days 7, 14, 21 and 30 are review days with mini tests; days 28 and 29 practise the Goethe-Zertifikat A1 format, including listening tasks.

Progress (days marked as done) is stored in the browser's localStorage.

## Audio

All spoken German was generated with Microsoft's neural German voices (Katja, Amala, Conrad, Killian) through the `edge-tts` package, then joined into one MP3 per day (`audio/day1.mp3` … `audio/day30.mp3`, plus `audio/extra.mp3` for the appendix) with a cue map in `audio/cues.json`. The page plays the right segment with the Web Audio API. If a clip is missing or the audio cannot be loaded, the browser's own speech engine is used as a fallback.

To regenerate after changing any German text:

```
node tools/extract-texts.js                # collects every playable text into tools/texts.json
.venv/Scripts/python tools/gen_audio.py    # generates missing clips into tools/cache/ (needs internet)
node tools/pack-audio.js                   # rebuilds audio/*.mp3 and audio/cues.json
```

One-time setup for the second step: `python -m venv .venv && .venv/Scripts/pip install edge-tts`. Clips are keyed by voice and text, so only new or changed texts are generated.

## Files

| File | Contents |
|---|---|
| `src/page.html` | Styles, the rendering engine, the start page and the appendix pages (the page as the artifact host publishes it) |
| `index.html` | Generated by `node build.js`: `src/page.html` wrapped as a complete document, for GitHub Pages or plain viewing |
| `data/week1.js` … `data/week4.js` | The 30 lessons |
| `data/appendix.js` | Verb list with participles, survival phrases |
| `data/voices.js` | Speaker-to-voice mapping and the clip key function, shared by the page and the tools |
| `audio/` | Per-day audio and the cue map |
| `tools/` | The three audio pipeline scripts |
| `serve.js`, `build.js` | Local preview server and the wrapper build |

`src/page.html` is written as page content only, without `<!doctype>`, `<html>`, `<head>` or `<body>`, because the Claude artifact host wraps it in its own skeleton at publish time. Run `node build.js` after editing it to refresh `index.html`.

## Lesson data format

Each lesson is one object pushed onto `window.LESSONS`:

```js
{
  day: 9,
  title: "Mein Tag",                 // German title on the yellow plate
  en: "Daily routine …",             // English subtitle
  mins: {warmup:3, dialogue:5, vocab:7, grammar:7, practice:6, speak:2},  // optional overrides
  labels: {grammar: ["Wiederholung", "Review"]},                          // optional section renames
  goals: ["…"],
  warmup: { intro: "…", items: [["prompt", "answer"]] },
  dialogue: { title: "…", scene: "…", lines: [["Speaker", "German", "English"]], note: "…" },
  vocab: [["der Tisch", "die Tische", "table"], ["heißen", "to be called"]],   // [German, plural, English] or [German, English]
  grammar: [{ h: "heading", body: "<p>HTML</p>" }],
  practice: [{ h: "A. …", note: "…", items: [["question", "answer", "optional remark"]] }],
  listen: [{ text: "German text to play", q: "question", a: "answer" }],       // optional
  speak: "<p>HTML</p>",
  cando: ["…"],
  tip: { h: "heading", body: "<p>HTML</p>" }
}
```

Speakers are mapped to voices in `data/voices.js`; add new speaker names there. Strings marked HTML may contain markup; the others are escaped when rendered.
